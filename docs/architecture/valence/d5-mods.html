Architecture · the repository's mods

How the mods and Companion fit together

Two mods, one hand-off

boomi-runtime gives a session its own temporary runtime and writes Companion's .env, so Boomi Companion builds and tests on it. The dashboard doesn't need the runtime mod, but shows its state when it's there.

The dashboard only reads

It reads the other mods' state and never writes it: only a value's owner writes it. It watches Companion through the shell commands Claude runs, not through any API of Companion's.

A mod set aside

boomi-standards held Companion's components to a team's standards before they reached Boomi. It's set aside and tracked in IDEAS.md. The dashboard already reads its state, so it will show what was blocked once the mod is back.
