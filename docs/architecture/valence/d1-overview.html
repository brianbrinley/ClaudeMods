Architecture · boomi-dashboard

How boomi-dashboard plugs into Claude Code

Events in, drawing out

Claude Code raises an event (tool.call, turn.*, prompt.submit, session.start, ui.render). One module hooks them, and answers ui.render with what to draw: the pane, the Prompt tab, the banner, the status line and toasts.

Logic stays testable

Anything that needs no engine call is a plain function in its own file, with unit tests that call it directly. Helpers that take $ stay in the hooks module, because the engine follows $ only within one file.

Reads out, installs nothing

It reads Companion's docs, polls Boomi's API, and runs git fetch once a day. A model is called only to rewrite a prompt or draft guide edits. Nothing installs unless you run /bc-dashboard upgrade.
